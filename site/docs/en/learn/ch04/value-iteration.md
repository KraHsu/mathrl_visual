# Value iteration: one optimality backup at a time

Value iteration is the most direct way to turn the Bellman optimality equation into a planner. Keep a candidate value vector, compute every action backup against that frozen vector, retain the largest backup at each state, and repeat.

<a id="learning-goals"></a>

## Learning goals

After this unit, you should be able to:

1. write one synchronous value-iteration sweep from a joint transition model;
2. recover a greedy policy from the same action backups;
3. explain why an intermediate $v_k$ is not automatically a state value;
4. distinguish a Bellman residual, an update size, and a sweep budget; and
5. diagnose in-place updates or outcome-wise maximization as different algorithms.

<a id="operator"></a>

## From $T_*$ to an executable recurrence

For a frozen vector $v_k$, calculate

$$
q_k(s,a)=B_{v_k}(s,a)
 =\sum_{s',r}p(s',r\mid s,a)
 [r+\gamma v_k(s')].
$$

Then perform the two logical reads:

$$
a_k^*(s)\in\arg\max_{a\in A(s)}q_k(s,a),
\qquad
v_{k+1}(s)=\max_{a\in A(s)}q_k(s,a).
$$

The first expression supplies a greedy policy for this iteration; the second is exactly

$$
v_{k+1}=T_*v_k.
$$

If several actions tie, any one of them is a valid deterministic representative. A visualizer should nevertheless retain the whole maximizing set, because throwing away a tie changes what the user can audit even when it does not change the value vector.

For a terminating state $s_T$, the site uses a fixed continuation value $v(s_T)=0$ and no decision row. It is not an action with five zero-valued choices; it is a boundary condition.

<a id="synchronous"></a>

## Freeze first, commit second

One sweep has a strict read/compute/commit order:

1. copy $v_k$ as the read-only input;
2. for every nonterminal state and every requested action, enumerate all stochastic outcomes;
3. sum the weighted terms to obtain each $q_k(s,a)$;
4. choose the maximum action backup and record its tie set; and
5. commit all states together as $v_{k+1}$.

Updating state $0$ and immediately using its new value while computing state $1$ produces an asynchronous or Gauss–Seidel-like variant. Such a variant can be useful, but it is not the synchronous recurrence above and should not be silently labelled “one sweep.”

The order of the stochastic calculation matters just as much. The planner computes

$$
\max_a\;\mathbb E_{s',r\mid s,a}[r+\gamma v_k(s')],
$$

not

$$
\mathbb E[\max_a(r+\gamma v_k(s'))].
$$

The latter gives the agent a chance to see the random outcome before choosing, which is a different information pattern.

<a id="algorithm"></a>

## A compact algorithm

The following pseudocode is deliberately explicit about what is frozen and what is reported:

```text
input: model p(s', r | s, a), discount γ, initial vector v0
repeat until a declared stopping rule fires:
    old ← copy(v)
    for each nonterminal state s:
        for each legal action a:
            q[s,a] ← Σ_{s',r} p(s',r | s,a) · (r + γ · old[s'])
        greedy[s] ← argmax_a q[s,a]
        next[s] ← max_a q[s,a]
    next[terminal] ← 0
    residual ← max_s |max_a q[s,a] − old[s]|
    update ← max_s |next[s] − old[s]|
    v ← next
return v, greedy, residual, update
```

The residual in the pseudocode is the Bellman residual of the **old** vector. After committing `next`, a UI may also report the residual of the current vector, $\|T_*v-v\|_\infty$. Naming which vector the number belongs to prevents off-by-one interpretations in a trace.

<a id="intermediate-values"></a>

## Intermediate vectors are operator iterates

It is tempting to attach a policy subscript to every $v_k$. That is generally invalid. Unless $v_k$ happens to solve

$$
v_k=T_{\pi}v_k
$$

for some policy $\pi$, it is not the value of that policy. Value iteration only promises that the sequence is generated by $T_*$ and, under the Chapter 3 assumptions, converges to $v_*$. Consequently $q_k(s,a)$ is an action backup against a candidate vector, not necessarily the action value $q_\pi$ of a policy.

This distinction is useful rather than merely pedantic: it allows a planner to stop early and still expose a certified residual bound, while honestly labelling the result as an approximation.

<a id="shared-grid"></a>

## A hand-check on the shared Grid World

With the baseline 4×4 model, $v_0=0$, $\gamma=0.9$, and no wind, the first synchronous sweep is

$$
v_1=(-0.04,-0.04,-0.04,-0.04,
-0.04,-0.04,-0.04,-0.04,
-0.04,-0.04,-0.04,1,
-0.04,-0.04,1,0).
$$

Only immediate rewards are visible at this point because every continuation value in $v_0$ is zero. A second sweep propagates the goal reward one step farther. Under the same fixed configuration, six sweeps reach the displayed tolerance and give (rounded to six decimals)

$$
v_6=(0.426686,0.518540,0.620600,0.734000,
0.518540,0.426686,0.734000,0.860000,
0.620600,0.734000,0.860000,1,
0.734000,0.860000,1,0).
$$

The first and final vectors are useful goldens, not an argument that six sweeps is a universal stopping rule. Change $\gamma$, wind, rewards, or tolerance and the required work changes.

<a id="stopping"></a>

## Stopping without overclaiming

Three quantities answer different questions:

| Quantity | Definition | What it can justify |
| --- | --- | --- |
| current residual | $\|T_*v_k-v_k\|_\infty$ | with $0\leq\gamma<1$, an error certificate $\|v_k-v_*\|_\infty\leq\text{residual}/(1-\gamma)$ |
| update size | $\|v_{k+1}-v_k\|_\infty$ | how much this sweep changed the vector; not by itself a fixed-point proof |
| sweep cap | $k=K_{\max}$ | that the work budget ended; call the result truncated if residual remains above tolerance |

At a high discount factor, the residual certificate becomes wider because of $1/(1-\gamma)$. The lab therefore shows both the raw residual and the scaled bound rather than colouring a vector “exact” merely because it stopped moving much.

<a id="complexity"></a>

## Cost and implementation checks

For $n$ states, at most $m$ actions per state, and $d$ explicit outcomes per state–action pair, one synchronous sweep costs $O(nmd)$ arithmetic operations and stores $O(n+ n m)$ values if the action ledger is retained. The model itself can be streamed, but every action backup must be complete before its maximum is selected.

Before trusting a run, check:

- probabilities in each outcome row are nonnegative and sum to one;
- rewards and all computed values are finite;
- terminal rows have no fabricated policy actions;
- the old vector is not mutated while a sweep is being computed;
- tie masks agree with the displayed action values within the documented tolerance; and
- a wind or hazard changes the outcome distribution, not the point at which the action is chosen.
