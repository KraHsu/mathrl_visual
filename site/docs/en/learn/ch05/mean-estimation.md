# Mean estimation: the small model-free problem

Monte Carlo control becomes less mysterious when reduced to one question: how can a learner estimate the mean of a random variable without knowing its distribution? State values and action values are means of returns, so this small problem contains the statistical core of the whole chapter.

:::

<a id="learning-goals"></a>

## Learning goals

After this unit, you should be able to:

1. write both the distribution-based and sample-based mean;
2. update a running mean without storing every observation;
3. explain why independent, identically distributed samples matter; and
4. identify what a return estimate can and cannot certify.

<a id="two-views"></a>

## Two ways to answer the same question

Let $X$ take values in a finite set. If its probability mass function is known, the expectation is a weighted sum:

$$
\mathbb E[X]=\sum_xp(x)x.
$$

If the mass function is unavailable but observations $x_1,\ldots,x_n$ are available, use the sample average:

$$
\bar X_n=\frac1n\sum_{i=1}^{n}x_i.
$$

The first calculation is exact for the supplied model. The second is an estimator whose value depends on the observations. Calling both numbers “the mean” without stating their information source hides the model boundary.

<a id="coin-example"></a>

## A reproducible coin thought experiment

Suppose a fair coin is encoded as $+1$ for heads and $-1$ for tails. A known model gives

$$
\mathbb E[X]=0.5(1)+0.5(-1)=0.
$$

Now imagine that the learner sees the sequence

$$
(1,1,-1,1,-1,-1,1,-1).
$$

The eight-observation estimate is $\bar X_8=0$. A different eight flips can produce $0.25$ or $-0.5$ even though the underlying mean is unchanged. The discrepancy is sampling error, not evidence that the coin's definition changed.

For a quick sanity check, keep a pair of counters:

| quantity | value for the sequence above |
| --- | ---: |
| observations $n$ | 8 |
| sum $\sum_i x_i$ | 0 |
| mean $\bar X_n$ | 0 |
| squared-deviation sum $\sum_i(x_i-\bar X_n)^2$ | 8 |

The last row is useful for a variance diagnostic but is not another estimate of the mean.

<a id="online-update"></a>

## The running-mean update

Storing all returns is unnecessary. If $m_n$ is the mean after $n$ observations and the next sample is $x_{n+1}$, then

$$
m_{n+1}=m_n+\frac{x_{n+1}-m_n}{n+1}.
$$

For example, starting with $m_0=0$, observations $2$, $-1$, and $4$ produce

$$
m_1=2,
\quad m_2=2+\frac{-1-2}{2}=0.5,
\quad m_3=0.5+\frac{4-0.5}{3}=\frac53.
$$

The final result agrees with $(2-1+4)/3=5/3$. This is the numerical pattern used by an MC return ledger: increment a visit count, then move the old estimate toward the new return by the reciprocal count.

<a id="law-of-large-numbers"></a>

## What more samples buy

For iid samples with finite variance,

$$
\mathbb E[\bar X_n]=\mathbb E[X],
\qquad
\operatorname{Var}(\bar X_n)=\frac{\operatorname{Var}(X)}{n}.
$$

Thus the estimator is unbiased and its variance shrinks with $n$. The standard deviation decreases like $1/\sqrt n$, not $1/n$: reducing typical noise by a factor of two takes roughly four times as many independent samples.

This is a statement about a sampling process, not a promise that every finite prefix is close. A return sequence generated by one slowly mixing trajectory can be strongly correlated. In that case the simple iid variance formula is a useful reference, not an automatic confidence interval.

<a id="mc-bridge"></a>

## From random variables to returns

Fix a policy and a state–action pair $(s,a)$. Each visit can produce a return sample $G_i(s,a)$. The action-value estimate is the same running mean:

$$
\widehat q_n(s,a)=\frac1n\sum_{i=1}^{n}G_i(s,a).
$$

The random variable is now “discounted future reward after this visit.” Its distribution depends on the policy, environment dynamics, discount factor, and termination rule. MC learning estimates it from episodes; it does not need to enumerate $p(s',r\mid s,a)$.

Two bookkeeping rules prevent common mistakes:

1. increment the count only when the chosen visit strategy says that a return is included;
2. use the return from that visit, not the immediate reward alone.

If the count is zero, display “unvisited” rather than $0$. A zero return from a visited pair and missing data are different facts.

<a id="audit"></a>

## A mean-estimation audit

When reading an MC trace, ask:

| Audit question | Evidence to request |
| --- | --- |
| What is the random variable? | a precise return definition and discount factor |
| Which observations entered the mean? | visit strategy and count |
| Are samples iid? | episode-generation assumptions or a correlation caveat |
| Is the estimate exact? | never for a finite sample; show uncertainty or residual language |
| Can the result be replayed? | seed, configuration, and episode trace |

The [Monte Carlo lab](/en/labs/ch05-monte-carlo) shows these fields next to the running estimate. Change only the seed to see that a different sample path can produce a different finite estimate while the environment definition remains the same.

<a id="check-yourself"></a>

## Check yourself

An estimator has seen returns $3$, $1$, and $-2$ for one pair. Its current mean is $2/3$. A fourth return is $5$.

The count becomes four and the new mean is

$$
\frac23+\frac{5-2/3}{4}=\frac32.
$$

If the fourth number was instead an observation from a different state–action pair, adding it would be a bookkeeping error even though the arithmetic still looks plausible. MC correctness begins with identifying the random variable and its visit key.
