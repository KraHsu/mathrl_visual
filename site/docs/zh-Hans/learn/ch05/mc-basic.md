# MC Basic：用回报替代模型评估

策略迭代有一个清晰的两步故事：先评估当前策略，再改进策略。MC Basic 保留这个故事，却更换评估工具。它不再求解基于模型的不动点方程，而是在当前策略下生成回合，把从回合起始状态—动作对得到的回报做平均。

::: info 实验调度说明
浏览器实验给 **MC Basic** 使用覆盖 75 个非终止状态—动作对的确定性字典序扫描，给 **MC Exploring Starts** 使用独立的带种子排列。两种调度都让带种子的运行可审计，但不表示普通环境会自然地从每个对开始。Basic 默认使用 **initial（初始）**，只记入被强制选择的起点对；Exploring Starts 则用于展示 **first（首次）** 或 **every（每次）** 访问。引擎在每个完整回合后改进控制策略；“每批回合数”只决定一次按钮操作生成多少个这样的回合。
:::

::: info 原创伴读说明
下面的小型例子和伪代码是原创解释材料。它们引用上游 MC Basic 主题，但不复制原书的算法框、图、正文或数值示例。

<a id="learning-goals"></a>

## 学习目标

完成本单元后，你应该能够：

1. 把基于模型的策略迭代映射到 MC 替代过程；
2. 识别 MC Basic 采用的初始访问选择；
3. 从完整回合计算动作价值估计；
4. 解释回合长度和重复起点为何影响准确性；
5. 把有限运行标注为估计，而不是精确的策略评估。

<a id="policy-iteration-bridge"></a>

## 与策略迭代的桥梁

已知模型时，策略迭代会评估

$$
v_{\pi_k}=T_{\pi_k}v_{\pi_k},
$$

然后计算每个动作备份 $q_{\pi_k}(s,a) 并改进策略。模型无关学习器不能直接执行 $T_\pi$ 中的期望，但可以在 $\pi_k$ 下收集回合，把回报当作 $q_{\pi_k}$ 的样本。

若回合从 $(S_0,A_0)=(s,a)$ 开始，MC Basic 记录

$$
G_0=R_1+\gamma R_2+\cdots+\gamma^{T-1}R_T,
$$

并只更新对应的状态—动作对：

$$
N(s,a)\leftarrow N(s,a)+1,
\qquad
Q(s,a)\leftarrow Q(s,a)+\frac{G_0-Q(s,a)}{N(s,a)}.
$$

该状态—动作对积累足够回合后，策略可以依据当前 $Q$ 表选择最大动作。因此策略改进是模型无关的，但它仍然是针对估计值的改进。

<a id="initial-visit"></a>

## 为什么叫“初始访问”

一个回合会访问很多状态—动作对，但 MC Basic 只把整个回合的回报归给第一个对。如果回合从 $(s_2,a_{\mathrm{east}})$ 开始，后来又访问 $(s_2,a_{\mathrm{wait}})$，后一次访问会被这个估计器忽略。这个选择刻意保持简单：一个回合、一个回报样本、一个表项。

这种策略让策略迭代的类比容易追踪，但会浪费信息。后面的[探索性起点](./exploring-starts)页面会复用相同的后缀。“初始访问”不是说第一次访问在统计上更优，而是一条成本清晰的采样规则。

<a id="episode-length"></a>

## 回合长度决定能够学到什么

假设正奖励只有到达很远的终止状态才能得到。如果每个回合都在到达该状态前截断，所有回报可能都是零（或只包含中途惩罚）。这样的 $Q$ 表内部可以自洽，却仍然无法显露有用路线。

考虑一个原创链：

```text
起点 ──1 步──> 中继 ──1 步──> 目标
```

第一步代价为 $-0.1$，第二步带来 $+1$，且 $\gamma=0.9$。从 `起点` 出发的完整回合回报是 $-0.1+0.9(1)=0.8$；一步截断只能看到 $-0.1$。两个样本都没有“错”，它们回答的是不同的时间范围问题。学习器必须记录回合是自然终止，还是被时间上限截断。

<a id="algorithm"></a>

## 透明的 MC Basic 循环

下面的版本只为可复现性固定了一个确定性并列规则；生产学习器可以保留全部并列动作。

```text
初始化 Q(s, a)、count(s, a) 和策略 π
对每个策略轮次重复：
  按实验文档规定的起点对调度收集回合
  对每个回合：
    按 π 生成完整（或明确标记为截断）的轨迹
    从起点反向计算折扣回报 G
    count(s0, a0) += 1
    Q(s0, a0) += (G - Q(s0, a0)) / count(s0, a0)
  对本回合影响到的每个状态：
    π(s) ← argmax_a Q(s, a) 的确定性代表
直到回合预算用完
```

这个循环有两个不同的计数器：回合贡献统计样本，策略轮次决定何时改进。把它们合并成一个“迭代”编号，就无法判断变化来自新回报还是新策略。

<a id="worked-trace"></a>

## 一个状态—动作对的计算轨迹

假设三个完整回合从同一对开始，回报依次为 $0.4$、$1.0$ 和 $-0.2$。运行表如下：

| 回合 | 回报 $G$ | 次数 $N$ | 更新后的 $Q$ |
| ---: | ---: | ---: | ---: |
| 1 | 0.4 | 1 | 0.4 |
| 2 | 1.0 | 2 | 0.7 |
| 3 | -0.2 | 3 | 0.4 |

第三个回合后的估计是 $(0.4+1.0-0.2)/3=0.4$。第二个回合后就改进策略，与第三个回合后才改进策略，看到的估计不同。两种调度都可以明确规定，但不应在轨迹中悄悄混用。

<a id="limits"></a>

## MC Basic 不保证什么

MC Basic 适合教学，但样本效率较低：

- 需要从每个重要状态—动作对重复生成回合；
- 丢弃同一回合中后续访问产生的回报；
- 有限回合预算会留下未访问或噪声很大的表项；
- 用不准确估计改过的策略，之后可能还要修正。

在覆盖充分且满足相应回合假设时，样本均值可以接近对应动作价值。浏览器里运行 20 个回合，即使箭头看起来稳定，也不是最优性的证明；应同时报告访问次数和回合生成策略。

<a id="lab-connection"></a>

## 在实验中观察

打开 [Monte Carlo 实验](/zh-Hans/labs/ch05-monte-carlo)，选择 **MC Basic**，把访问策略设为 **initial（初始）**，然后重置。回合面板应显示每回合只记入一个起点回报，且计数只在起始对上增加。改变回合上限或随机种子，观察策略可以变化，而模型的任何一行都没有改变。

不要把 MC Basic 的样本数直接与第四章的精确备份数比较：前者是随机回报观测，后者是确定性的期望计算。

<a id="check-yourself"></a>

## 自测

一个回合从 $(s,a)$ 开始，访问 $(u,b)$ 两次后终止，折扣回报为 $G=2$。在 MC Basic 下，哪些计数变化？只有 $N(s,a)$ 增加 1；$N(u,b)$ 不变。如果实现把所有访问过的对都加一，它实现的就是另一种访问策略。
