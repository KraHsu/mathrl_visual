# 轨迹、回合与终止

一串连续交互可以用多种方式切分。有些切分来自任务本身，有些只是为了记录或测试而人为停止。终止语义必须清楚，因为它决定了哪些奖励共同组成一次完整结果。

<a id="trajectory-vs-episode"></a>

## 轨迹不一定是回合

**轨迹**是按时间排列的状态、动作与奖励序列。它可以是一次完整运行，也可以是开头的一小段，或从持续交互中间截取的窗口。

**回合**则是由任务定义的单位：它按初始化规则开始，在终止规则触发时结束。因此：

- 每个完成的回合都包含一条轨迹；
- 一段轨迹前缀不一定构成完整回合；
- 持续式任务可以产生任意长的轨迹，却根本不产生回合。

假设机器人走了五步后仍在移动。前五次状态转移是一段有效轨迹，但只有任务规则规定“第五步结束运行”时，它才是完整回合。

<a id="terminal-vs-goal"></a>

## “目标”描述含义，“终止”描述控制流程

**目标状态**表示任务设计者认为它值得到达；**终止状态**会结束当前回合。这两个属性经常同时出现，但彼此都不能推出对方。

| 情形 | 是目标？ | 会终止？ | 解释 |
| --- | :---: | :---: | --- |
| 包裹送达并结束班次 | 是 | 是 | 成功的终止结果 |
| 电池彻底耗尽 | 否 | 是 | 失败的终止结果 |
| 一条路线中送达一个包裹 | 是 | 否 | 值得到达的检查点，任务继续 |
| 普通走廊位置 | 否 | 否 | 中间交互状态 |

如果把所有目标都当成终止状态，就无法描述包含多个检查点的任务；如果把所有终止状态都叫作目标，又会掩盖失败与安全停机。

<a id="absorbing-state"></a>

## 吸收状态是一种建模扩展

有时数学模型会继续描述“回合结束以后”的状态转移。我们可以加入吸收状态 $s_{\mathrm{abs}}$，使它永远转移到自身。采用零奖励约定时，对其中每个占位动作 $a$ 都有

$$
p(s_{\mathrm{abs}},0\mid s_{\mathrm{abs}},a)=1.
$$

吸收状态与会返回终止信号的环境接口，是停止概念的两种表示，但不是同一个对象。环境实现可以返回 `done` 并拒绝下一个动作；数学扩展则可以继续产生自环。进入吸收状态后的奖励必须明确写出，零奖励只是约定，并非自然定律。

<a id="episodic-vs-continuing"></a>

## 回合式任务与持续式任务

**回合式任务**有自然或人为设计的停止规则，例如走完迷宫、完成一次配送或违反安全约束。之后，系统按初始化规则开始新回合。

**持续式任务**的目标没有自然终点，例如持续调节楼宇温度、平衡网络流量或长期运行一项服务。为了让测试能够结束，我们仍可能在 10,000 步后停止模拟。这个外部时间限制属于**截断**，并不自动成为所建模任务的终止事件。

这个区别会影响怎样解释[回报](./returns)：完整回合的回报累积到终止时刻；持续任务被截断后得到的有限记录，只是一个观察窗口，除非目标本身另有定义。

<a id="worked-example"></a>

## 原创例子：校园配送车

考虑一辆遵循下列规则的配送车：

1. 在图书馆送达一个包裹是目标检查点，但路线继续；
2. 所有包裹送达后回到车库，是成功终止事件；
3. 电池耗尽，是失败终止事件；
4. 为了便于数学记账，两种终止事件都可以继续转入零奖励吸收状态。

从离开车库到第一次在图书馆送达包裹，这个序列是一段轨迹，却不是完整回合。以回到车库或电池耗尽结束的完整序列才是回合。如果研究者在两种事件都没发生时于第 200 步停止模拟，那么运行被截断了，并不能说明配送车到达了终止状态。

当前 [Grid World 概念实验](/zh-Hans/labs/ch01-gridworld) 使用更简单的约定：到达菱形目标后立即结束回合，危险格虽然代价较高，但不会终止。

<a id="self-check"></a>

## 自检

判断下面三种情形。

1. 智能体违反安全规则，因此游戏结束；
2. 监控脚本记录一个永不停止控制器的前 50 步；
3. 机器人到达一个取货点后，继续前往另外两个取货点。

::: details 查看答案
违反安全规则是终止事件，但不是目标；前 50 步是被截断的轨迹，不一定是回合；在给定规则下，取货点是目标或检查点，但不是终止状态。
:::
